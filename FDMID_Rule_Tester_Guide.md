## About This Guide

This document walks you through six test scenarios for the new FDMID auto-generation attribute rule. The rule assigns a unique integer FDMID to every new address range event — whether created by a user or generated by an LRS split operation.

**You do not need to understand Arcade or attribute rules to run these tests.** Follow the steps exactly, record what you see, and fill in the feedback form at the end.

---

## Section 1 — Prerequisites

Before you begin, confirm all of the following:

- [ ] ArcGIS Pro 3.3.5 installed and connected to the Enterprise geodatabase
- [ ] You have editor access to `SDEADM.E_AddressRange`
- [ ] The DBA has confirmed the attribute rule is applied to the feature class
      *(If unsure: open Layer Properties → Attribute Rules — `AutoGenerateFDMID` should appear in the list)*
- [ ] You have the LRS Event Editor or Roads & Highways extension enabled for split tests (T-3, T-4, T-5)
- [ ] *(Optional)* SQL/database access for the uniqueness check (T-6)

> **Important:** FDMID only populates **after you save your edits** (click Save on the Edit tab). It will not appear while the record is still being edited.

### T-3 — LRS Split: Segment With More Nearby Civic Addresses Keeps the FDMID

**Purpose:** Confirm that after a split, the segment surrounded by more civic address points keeps the original FDMID, and the other segment receives a new one.

**Setup:**

- Identify an existing Address Range event (note its current **FDMID**, e.g., `10010`).
- The event should run through or alongside an area where **one portion of the route has noticeably more civic address points** nearby than the other. Open `LND_civic_address` in the map to visualize address density along the route.
- Note the **FDMID before the split**.

**Steps:**

1. Start an edit session.
2. Using the LRS Event Editor split tool, split the Address Range event at a point where one side of the split has clearly more civic addresses nearby (within ~50 m of the route) than the other side.
3. Save your edits.
4. Open the attribute table and find both new records (the retired parent will also appear with a TODATE set — ignore it).

**Expected result:**

- The new segment whose geometry passes through the **address-dense** area retains the **original FDMID** (e.g., `10010`).
- The new segment in the **address-sparse** area receives a **new, different FDMID** (e.g., `10043`).
- The two new records have **different FDMIDs**.

### T-6 — Uniqueness Check (SQL)

**Purpose:** Confirm there are no duplicate FDMID values in the active event table after all the above edits.

> This test requires SQL/database access. If you do not have access, mark as N/A and note it in the feedback form.

**Steps:**

1. Connect to the Enterprise geodatabase with a SQL client (e.g., SQL Server Management Studio, DBeaver, or ArcGIS Pro's Database Connection query tool).
2. Run the following query against the **active** events (TODATE IS NULL):

```sql
SELECT
    FDMID,
    COUNT(*) AS occurrences
FROM SDEADM.E_AddressRange
WHERE TODATE IS NULL
  AND FDMID IS NOT NULL
GROUP BY FDMID
HAVING COUNT(*) > 1
ORDER BY occurrences DESC;
```
